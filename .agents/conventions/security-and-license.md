# 安全、许可与合规红线

MIT 开源项目，这几条是硬边界，CI 或 review 发现即打回。

## 1. 依赖许可准入

**允许**：MIT、BSD（2/3-Clause）、Apache-2.0、ISC、PSF 系。
**禁止**：GPL（任何版本）、AGPL、LGPL、SSPL，以及许可不明的包。

理由：本项目自身是 MIT，混入 copyleft 依赖会污染下游使用者的许可义务，也对商业采用不友好。

引入依赖前：

1. 确认许可，写入 PR 描述；
2. CI 用 `pip-licenses`（后端）与 `license-checker`（前端）扫描，出现禁用许可即失败；
3. 优先选择活跃维护、类型定义完善、体积合理的实现。

## 2. 标准文本版权

- GB/T 48000.3—2026 **正文不入库**：仓库里只保留**条款编号 + 自撰的简短描述性引用**（如 `6.2.2 → 标准实体类`）。
- 标准 PDF 不放进 `samples/` 或任何目录。
- 界面上引用标准条款时，引用编号与自撰描述，不复制原文段落。
- 「引用既有emannan的差异解释」（附录性质、日期词法、`Clause` 消歧、示例域名）以自撰文档形式留痕，不抄原文。

理由：国家标准文本受版权与标准出版权保护， outright复制进开源仓库是明确的法律风险。

## 3. 数据脱敏

- 样例库、夹具、文档示例一律使用虚构数据：`example.org` 域名、`91310000DEMA000001` 形式的信用代码、虚构人名。
- 禁止把真实客户库结构、字段注释、业务数据写进仓库或测试夹具。
- 元数据库与被抽取的源库**物理分离**。

## 4. 凭据与连接安全

- 数据源凭据由后端持有，浏览器只拿到可展示配置与状态；不得出现在 API 响应、日志、导出包。
- 强制只读：连接器层拦截写语句；样例预览限行数、限时间。
- 凭据加密存储（M2 引入 `cryptography`，需确认 wheel 可用再装）。
- 日志脱敏：连接串、密码一律不落日志。

## 5. 漏洞报告

安全问题走私有渠道报告（SECURITY.md），**不要开公开 issue**。维护者在 issue 模板中已提供入口。

## 6. 贡献合规

- 项目采用 DCO（贡献者在提交信息末尾 `Signed-off-by`），不要求 CLA，降低个人贡献门槛。
- 所有贡献默认以本项目许可（MIT）授权分发。
