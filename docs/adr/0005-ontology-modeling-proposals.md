# 0005 — 本体工作稿校验与 AI 候选协议

日期：2026-11-20。范围：本仓库。此文记录工程选择，不作 GB/T 48000.3—2026 符合性认证。

## 背景与决定

本体工作装配、资源发布版本及历史本体版本具有不同身份。校验不能根据一个 `PUBLISHED` 状态猜测用户所见对象。HTTP 校验缺省采用 `WORKING`，历史检查显式传 `PUBLISHED` 和发布修订。报告绑定目标、工作修订、发布修订、内容摘要和检查器版本。

本体发布冻结资源闭包、规则正文和模板清单，验证本次固定输入，然后才推进发布指针。必需检查 `VIOLATION` 或 `NOT_RUN` 阻止发布。这是项目发布治理，不能解释成标准规定了特定 API 顺序。历史模板证据缺失返回 `NOT_RUN`，不查询当前模板猜测历史状态。

旧标签/定义补全继续使用原数组协议，修复目标归属、编辑基线、CAS、重复应用和事务审计。新的 `ontology-candidate/1.0` 是独立对象协议，Pydantic 为 Schema 真值源；OpenAPI 生成前端类型，运行时生成 JSON Schema。旧数组解析器不接受新的建模对象。

## 数据与事务边界

- `ontology_modeling_proposal` 保存作者、目标、固定上下文、生成幂等键和模型/提示词版本，绝不保存密钥。
- `ontology_modeling_revision` 保留不可变候选修订，区分模型原提议与人工修订。
- `ontology_modeling_validation` 保存程序报告及计划摘要。结构、引用、依赖、TBox、形状及实例检查的覆盖范围分别表述。
- `ontology_modeling_application` 保存成功事务收据及临时 ID 到正式资源的映射，和草稿资源、装配、规则、审计一起提交。

生成过程先读取最小授权上下文，再释放数据库事务等待有界模型请求，返回后重新检查上下文及模型配置修订。模型输出没有权限、状态、验证结论、正式资源 ID 或任意代码执行能力。

应用过程不调用模型。数据库写锁/草稿 CAS、候选修订、内容指纹、报告、计划摘要和人工确认必须一致。复用资产钉住不可变版本，创建资产保持 `DRAFT`，不调用资源或本体发布接口。任一写入失败由 API 回滚整个事务。

提交应答丢失不代表回滚。客户端保留原幂等键，通过 `applications/by-key` 查询结果；查询不到记录也不自动宣称失败或用新键重复应用。已提交后重复相同请求返回原收据，不重复创建资源。

应用在提交前失败且回滚成功后，API 用单独事务记录最小失败审计：操作者、目标、错误码与关联标识。该审计不保存输入材料、候选内容或异常文本；审计库不可用不覆盖原始业务错误。提交结果不明时不能写成已确认失败。

存在候选记录的本体保留审阅和应用历史；删除返回 `KG.RESOURCE_IN_USE` 及 `ontology_modeling_history_retained`，不级联抹去来源、报告或收据。

## 来源、适用范围与能力

模型只收到服务端分配的命名空间、资产和来源片段句柄。候选只能引用目录中的对象；材料中的指令始终是数据。资料传输由本次请求显式授权，不把已有模型配置视为任意资料传输许可。提议与来源解释不等于事实证据蕴涵。

企业业务使用 `BUSINESS`，不自动加入标准文本核心类型。标准数字化 profile 在核心规范包、官方命名空间和解释差异核准前保持不可用；不能以用户自报名称清单的 `all_core_present` 代表完整国标符合。

能力清单由服务端返回；Schema 可以识别未来构造，但编译器拒绝当前未支持项，并以 `NOT_RUN` 阻止应用。对象属性单端点 `ONE`、OWL 功能性与 SHACL 基数保持各自语义。支持集扩展时同时更新编译、执行、持久化、导出及正反例测试，不把字符串注解当执行结果。

文档辅助入口目前接受用户已授权的文本片段并生成内容哈希和行号。原始 PDF/标准正文不内置、不复制到仓库、不作为测试夹具。任意文件下载、自动抓取外部资料、OCR 与知识库来源授权是独立能力，不隐式开启。

## 兼容与部署

`0022` 增加校验绑定，`0023` 增加候选与收据表，`0024` 增加同义词。旧 IRI 不迁移改名，旧版本快照不改写。迁移必须先备份并在部署环境单独执行；本轮开发只对临时数据库运行迁移验证，不改现有业务库或模型配置。

前端文案走 zh-CN/en-US，后端返回错误码、结构化参数及枚举。实际业务实例未运行时必须显示 `NOT_RUN`。禁用新入口不删除已应用草稿或审计记录。

本体发布成功响应按项目统一约定改为 `ApiResponse[OntologyPublishOut]`；`revision` 与 `edit_revision` 位于 `data`。前端共用客户端已解包，浏览器测试调用方已同步；外部直接消费旧根字段的调用方必须迁移。业务域发布的现有行为没有在本轮扩大修改。
