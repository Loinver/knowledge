# 业务资产审计边界

日期：2026-11-07。状态：采用（PC14 用户确认）。

## 决定

资产审计使用独立 `asset_audit_log` 表，与账号登录审计分开。管理员通过
`GET /api/v1/asset-audit-logs` 按操作者、动作、对象、结果、关联 ID、时间检索；
服务端分页，时间输出 UTC。既有系统审计页同时提供两个独立列表。

事件仅包含操作者 ID、动作枚举、对象类别和 ID、变更前后数字版本、结果、
错误码、服务器生成的关联 ID 和时间。不采集凭据、请求/响应正文、资源名称、
业务数据或异常文本。对象尚未创建时 ID 为 null；未设置版本号的资产版本为
空对象；没有已保存版本时为 null，不伪造版本。

操作者 ID 与对象 ID 均不设置外键，账号或资产删除不影响历史。默认无限期
保留；应用没有更新、删除或自动清理入口。迁移允许空表回退；存在审计事件时
拒绝自动 downgrade，避免以回退代码为由删除历史。后续归档和保留期限需单独决定。

## 事务边界

`authorize_business_request` 在独立短会话完成身份解析，再为已声明的资产
写端点建立请求级上下文。`audit_asset` 声明动作和目标，创建端点在业务事务内
通过 `audit_created` 绑定新 ID。上下文与事件监听器仅绑定当前 Session。

事务首次建立时先锁定目标，再读取变更前的白名单版本列：SQLite 使用不命中行的
UPDATE 获取事务写锁，不修改值或时间戳；PostgreSQL 使用行锁，当前图谱指针使用
图谱表写互斥锁，因为不同目标图谱也会修改同一个当前指针。锁一直保留到业务事务结束。
这避免先读到旧版本、再等待并发变更后写入而形成错误的旧新版本对。
提交前 flush 业务变更、读取新版本、
把成功事件加入同一事务。审计插入失败则业务也回滚。业务异常时先回滚，再使用
独立 Session 尝试一次失败事件写入，不携带原请求的 ORM 对象。独立审计写入失败
不重试，只输出固定日志码与关联 ID，保留原业务错误。数据库整体不可用时无法
保证失败事件持久化；该缺口不会被伪装为成功。

已经提交后的响应序列化失败不会追加“变更失败”事件，因为业务已成功提交。
审计结果表达数据库变更是否成功，不等价于浏览器成功收到响应。

## 覆盖与边界

已接入类型/关系、业务域、本体、映射、命名空间、数据源、规则、枚举、条款、
装配模板的创建、编辑、发布、撤回、装配、删除等现有直接端点，以及手动切换
图谱当前版本。完整导入端点按相同接缝集成。旧 API/CLI 或直接调用领域服务时
没有 HTTP 操作者上下文，不据此追溯历史事件；本功能不回填历史。

异步抽取自动提升当前图谱、AI 建议间接修改资源、图谱视图模板不属于本次已声明
端点集合。后续扩展应显式携带真实操作者和具体资产目标，不能用请求正文推断或
把后台线程归因给最后访问的用户。领域服务不依赖 HTTP 或操作者全局变量。

读接口只有管理员权限；资产写权限仍沿用现有业务授权。认证失败不产生带伪造
操作者的资产事件；已认证只读角色对已声明写端点的拒绝记录为失败事件。

## 验证

`server/tests/test_asset_audit.py` 直接验证 HTTP 鉴权、版本快照、装配、编辑、
删除、图谱切换、提交失败、审计失败、回滚后的失败留痕、同资产双连接交错更新、
请求身份隔离和敏感排除。
`test_asset_audit_migration.py` 只在临时 SQLite 库验证空库、前一 head 升级
和历史保留。前端状态回归覆盖筛选、分页、过期响应、卸载取消和失败重试；
`e2e/asset-audit.spec.ts` 提供隔离库页面验收用例。
