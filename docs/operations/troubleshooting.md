# 常见问题与故障排查

核验日期：2026-11-26；各操作仅针对你管理的环境。先记录页面地址、时间、错误码、对象/运行编号和相关日志，去除口令、令牌、连接串及业务敏感内容。

| 现象                        | 优先检查                                                                  | 处理路径                                                                                           |
| --------------------------- | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `admin` 登录提示凭据错误    | 当前端口对应哪个 API 和数据库；账号是否在该库中；是否使用初始化生成的密码 | 不存在通用密码。先核对部署记录；预览账号与开发账号独立。用现有管理员签发重置，不要重跑 seed 当重置 |
| 提示尝试过多                | 同来源短期失败次数、可信代理配置                                          | 等待窗口结束，核对准确凭据后再登录，不删除审计或绕过限流                                           |
| 找回密码没有邮件            | 默认未启用自助重置，当前无内置邮件投递流程                                | 联系其他管理员签发一次性重置链接；唯一管理员丢失口令属于需授权的恢复操作，不提供后台绕过认证说明   |
| 页面有入口但操作403         | 登录角色、服务端授权、当前对象状态                                        | 查看[角色权限](../user-guide/roles-permissions.md)，刷新会话；隐藏按钮不是授权依据                 |
| 页面访问正常但 API 连接失败 | Vite 代理目标、后端进程、端口、环境变量工作目录                           | 确认开发4010→4000；隔离预览必须指向其独立API。本机代理影响 curl 时加 `--noproxy '*'`               |
| 数据源不可达                | 后端主机能否访问、驱动是否安装、只读凭据、绝对路径                        | 先做连接测试，再采集元数据；PG/MySQL 源驱动不等于元数据库驱动                                      |
| 表或字段不见了              | 元数据快照、源结构是否变更、选中数据源                                    | 重新采集元数据并核对映射；不要用旧样例推断真实结构                                                 |
| 保存报修订冲突              | 对象是否被其他页面/用户修改                                               | 保留当前输入并重新读取差异；不要无条件覆盖或删除并发参数                                           |
| 发布失败                    | 是否有需要发布的成员、校验违反、未执行项、冻结引用缺失                    | 打开对应报告，定位对象和规则；NOT_RUN 不能当成通过                                                 |
| 抽取有隔离或失败            | 运行统计、阶段状态、隔离原因、映射业务键与关系端点                        | 修正配置或源数据后重新运行；核对当前结果集是否仍指向上一成功结果                                   |
| 图谱没有最新数据            | 选择的是哪个结果集、运行是否成功、过滤条件                                | 选择准确结果集并清除不必要筛选，不以空画布推断数据库为空                                           |
| 文档处理一直排队            | worker 开关、应用进程、任务状态                                           | 检查 `KG_KNOWLEDGE_WORKERS_ENABLED` 和日志；不重复上传制造新任务                                   |
| 向量过期或语义搜索不可用    | 默认EMBEDDING模型、配置版本、文档索引状态                                 | 先核验模型服务，再重处理；关键词检索与语义检索可用性分别判断                                       |
| 问答不可用或没有答案        | CHAT/EMBEDDING默认、检索证据、模型协议响应                                | 检查能力提示；没有可引用证据时不能把空结果解释为确定的业务结论                                     |
| 连接或模型配置无法解密      | `KG_CRYPTO_KEY` 是否改变、是否对应该数据库                                | 恢复正确密钥；不要直接覆盖历史密钥或在日志打印解密值                                               |
| 升级后缺字段/表             | 目标库、Alembic版本、是否错误使用create_all                               | 在备份与维护窗口执行迁移；自动建表不会自动升级既有表                                               |
| 健康接口正常但业务异常      | 健康接口只检查应用响应                                                    | 分别检查数据库、外部源、模型与业务主链                                                             |

## 用户可提交的故障信息

提供模块、入口、对象编号、复现步骤、实际错误码和脱敏截图。涉及运行时带上 run_id 与图谱结果集编号；涉及知识库带上文档和处理任务编号。不要提交浏览器 storage、完整请求 Authorization、模型密钥或真实源库导出。

## 当前已知验收差异

设计改版后的部分历史 E2E 仍可能依赖旧布局选择器。失败时应核对截图、请求和业务状态，分别记录业务失败与测试定位失败；不得通过删掉冻结、权限或证据断言来制造通过。本轮具体结果见[验证记录](../maintenance/verification-2026-11-26.md)。
