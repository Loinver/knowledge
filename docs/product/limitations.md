# 能力边界、已知限制与商业化准备

核验日期：2026-11-26；基线 `9222236` 加未提交工作区。这里区分“有实现但受限”“源码风险”和“未验证”，不把建议列为已交付功能。逐项来源见[功能台账](feature-catalog.md)，本轮实测见[核验记录](../maintenance/verification-2026-11-26.md)。

## 当前成熟度

主链具备真实实现，已用隔离 SQLite 与浏览器抽查建模、数据到图谱、冻结证据及部分知识库和账户流程，适合业务试点与集成评估。这不等于每个模块、组合、异常路径和生产部署已经验收。没有依据承诺正式企业级 SLA、认证或指定规模。

## 已实现但有明确边界

| 范围           | 当前边界与使用影响                                                               | 采用前的处理                                                   |
| -------------- | -------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 权限           | 全局 ADMIN/EDITOR/VIEWER；无逐知识库ACL、字段权限或租户隔离                      | 共享部署前确认所有获授权读者可见范围；有隔离要求时单列需求     |
| 发布与并发     | 发布版本与编辑修订不同；部分接口的编辑令牌可选，布局为最后写入覆盖               | 使用当前页面提交上下文；多人同时编辑前确认具体对象保护范围     |
| 源连接         | SQLite路径位于后端；PG/MySQL源驱动未完整包含在默认依赖中                         | 在隔离目标环境验证驱动、只读权限、网络与字符类型               |
| 增量抽取       | 仅受支持的不可变追加整数主键/水位组合，不支持通用更新、删除、CDC和业务键融合组合 | 不符合条件使用受控全量，不能直接把时间戳字段当水位             |
| 抽取任务       | 进程内调度，运行进度/取消有内存状态；延后时间不是周期cron                        | 验证重启恢复与多副本行为后再制定调度保障；不宣称分布式可靠执行 |
| 图谱           | 邻域与节点/边有展示上限；当前结果集指针为共享全局状态                            | 缩小查询范围，切换结果前协调；截断不是来源无数据               |
| 知识文件       | UTF-8 TXT/Markdown/CSV；无PDF、Word、OCR；归档不是物理删除                       | 录入前转换并审核文本，制定保留策略；容量限值见知识库指南       |
| 语义检索与问答 | SQL存储向量并有界精确检索；问答为证据摘录，外部模型需显式配置                    | 验证业务召回与引用，不能承诺自由生成答案或任意规模向量检索     |
| RDF与推理      | 受支持子集；恢复为新建本体，规则不能保证无损往返；OWL RL不是完整DL               | 先预览再恢复；原数据库备份仍是灾备依据                         |
| 审计           | 账号与业务资产审计各有范围；不是全部数据访问日志或不可篡改认证系统               | 按实际合规需求评估保留、权限、导出与外部审计要求               |

标准符合性只到“部分符合”：通用建模与 RDF/OWL/SHACL 子集已实现，但核心标准实体、表1 的 34 个核心对象属性与部分 8.2 规则仍缺失，按[GB/T 48000.3—2026 能力映射](../development/ontology-standard-mapping.md)核对，不表述为通过认证。

## 源码审查发现，尚未逐项复现

以下不是本轮已确认的生产事故，也未在本次文档任务中修改业务实现。

| 发现                                                         | 使用影响与建议                                           | 来源                 |
| ------------------------------------------------------------ | -------------------------------------------------------- | -------------------- |
| 类型改名、布局与部分删除/发布缺客户端编辑修订约束            | 并发编辑保护不统一；按端点补隔离冲突测试，再决定修复范围 | SEM-003/004、ONT-002 |
| 条款删除未形成完整引用阻断                                   | 删除前人工检查关联规则与保留要求                         | GOV-001              |
| 映射删除会删除历史版本与预览，运行引用可能通过数据库外键报错 | 不以删除作为归档；有运行引用时可能缺少友好提示           | MAP-002              |
| 旧AI建议接口读取范围宽于创建者隔离的AI建模候选               | 业务输入应符合当前全局共享边界，不作为私有工作区         | ONT-005/006          |
| 业务域页面未设置资源维护责任域                               | 页面分组不能作为强制责任归属或访问控制                   | SEM-001              |
| 域发布响应未声明统一ApiResponse模型                          | 不能假定每个JSON端点都自动有同样外壳                     | API规范与SEM-001     |

## 未验证与商业化缺口

| 项目                   | 当前结论                                 | 建议的独立验收                                         |
| ---------------------- | ---------------------------------------- | ------------------------------------------------------ |
| 生产PostgreSQL及外部源 | 本轮未连接生产或外部库                   | 迁移、并发锁、驱动兼容、源权限和恢复演练               |
| 模型服务               | 本轮未调用真实CHAT/EMBEDDING供应商       | 协议兼容、超时失败、费用与数据边界、业务效果           |
| 高可用与容量           | 无本轮多实例、容量或长稳证据             | 根据业务量制定负载、重启恢复、监控、备份和故障切换计划 |
| 统一身份与组织隔离     | 未实现SSO、MFA、多租户或细粒度ACL        | 独立产品与安全设计，不在销售材料中写成现有能力         |
| 计费、SLA与认证        | 不属于当前实现                           | 需要独立商务、运维及合规工作，不从技术文档推导承诺     |
| 历史数据生命周期       | 知识历史索引与归档保留，没有完整自动清理 | 先确定保留/删除政策，再评估业务实现                    |
