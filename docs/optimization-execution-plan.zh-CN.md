# 知识中台优化实施方案与进度

> 基线日期：2026-09-24。本文记录本轮审查后获授权的改进范围、实施顺序和验收口径。它描述当前工作区的状态，不代表代码已发布或现有用户数据库已迁移。

## 目标与边界

当前产品定位以 [README](../README.md) 为准：自托管的语义建模与 SQL 知识抽取平台，主链路为本体建模 → 数据接入 → 映射 → 抽取 → 图谱及证据追溯。先修复安全边界和主任务可达性，再依据规模数据决定任务化和检索方案。文档、网页、IM、向量问答、多租户与插件生态属于条件项；在产品目标、数据量及复用方明确之前不预建模块。

本轮不迁移或清理现有用户数据库，不覆盖工作区已有的 `SECURITY.md` 删除、`Designer.vue` 修改及未跟踪审查稿。凭据格式迁移必须在备份和停写后单独执行。

## 关键实施决策

### 服务端授权

以服务端路由依赖作为默认入口：业务读请求需有效会话，写请求需 EDITOR 或 ADMIN；用户管理与审计日志仍由 ADMIN 限定。前端路由守卫只承担页面导航，不视为安全边界。现有账号模型只有 ADMIN/EDITOR/VIEWER 单角色，资源级、字段级和租户权限不在本轮伪装成“已完成”。新增权限矩阵测试必须覆盖匿名用户及三个角色，E2E 的 API 种子请求必须带注册后获得的访问令牌。

### 凭据格式与迁移

新值使用带格式前缀的 AES-GCM 和逐条随机 nonce。无前缀旧值只为过渡保留读取能力；新建请求拒绝在 `params` 内传密码等秘密。迁移脚本 `scripts/migrate_datasource_credentials.py` 默认只演练并回滚；执行写入必须显式使用 `--apply --backup-confirmed`。若换密钥，用环境变量 `KG_OLD_CRYPTO_KEY` 提供旧密钥，新密钥由 `KG_CRYPTO_KEY` 提供；不通过命令行参数传递秘密。部署前必须备份、停写，并在数据库副本上核对迁移记录数和连接测试。脚本不得在应用启动时自动改写用户数据。

### 分页契约

现有部分列表为数组响应，直接改成分页对象会破坏未同步调用方。首选新增可版本化的分页读取入口，并让业务页面和选择器迁移；旧接口保留至调用方核对完成。方案对比：

| 方案                         | 优点                       | 代价                                 | 选择条件                         |
| ---------------------------- | -------------------------- | ------------------------------------ | -------------------------------- |
| 新增分页入口、保留旧数组接口 | 可逐页迁移，兼容现有调用方 | 过渡期维护两种读取形式               | 当前默认                         |
| 统一改写既有列表响应         | 契约更简洁                 | 所有前端、测试与外部调用方须同步升级 | 明确无旧调用方或进入破坏性版本时 |

### 抽取与检索

先测量代表性源表与图谱规模，记录响应时长、峰值内存、失败回滚和当前结果集指针。不在缺少规模目标时直接引入队列。短任务可保留同步执行并设上限；需要分钟级运行、取消或重试时再采用持久任务记录与 worker。知识检索先验证名称/IRI/字段的服务端搜索，再依据召回评测决定全文或向量方案；AI 映射建议须显示来源、置信度并经人确认。

## 交付门禁和待确认项

每组改动依次完成定向测试、相关集成测试、`make lint`、`make test`、OpenAPI 类型检查及隔离 Playwright 主流程。安全/持久化变更还需独立复核、临时库迁移和失败回滚验证。命令启动或部分用例通过不算整项验收，记录“已验证、局部验证、未验证”三种状态。许可规则当前与脚本白名单不一致；维护者需选择替换依赖或批准明确的包级例外，不能静默扩大允许范围。

仍需产品方确认：目标是否扩展为通用文档知识中台；预计用户、租户、源表和图谱规模；生产数据库与部署入口；邮件服务、备份/RPO/RTO、SLA；真实 PostgreSQL/MySQL 源库验收环境。这些输入决定 P1 任务化及后续平台能力的最终方案。
