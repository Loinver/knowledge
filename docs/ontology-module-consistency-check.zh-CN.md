### 2.2 设计器的新发现（本轮）

**N1 · 业务域入画布后画布上没有任何体现（数据与呈现不一致）**

`Designer.vue:123-124` 的 `nodes` **只由 `canvasTypeIds` 构建**，`edges` 只由 `canvasRelationIds` 构建。业务域可以加入画布（`canvasDomainIds`，资源池里会出现在「已入画布」并高亮），但**画布上既不画节点也不画分区**——用户看到「已入画布」里有它，画布上却找不到，属于「状态说有、画面没有」。

**N2 · 画布没有按业务域分区**

`implementation-plan.zh-CN.md` §4.2.4 要求设计器「移植 demo 布局算法：**分区**、贝塞尔折行、标签贪心避让」。实测画布只有节点 + 边 + 网格底纹，**没有任何分区（泳道/背景块）与分区标题**。代码里搜不到 `partition` / 分区 相关实现。

**N3 · 本体自身的基本信息不可编辑**

`ontologyApi.update`（后端 `PUT /ontologies/{id}`）**从未被任何页面调用**。本体库列表只有「新建 / 设计器 / 发布」，设计器顶栏只有「选择本体 / 自动布局 / 发布」——**本体的机读名之外的标签与定义没有任何修改入口**。这与上一轮修掉的「实体类型无法编辑基本信息」是同一类缺口。

**N4 · 图例语义与设计不符**

设计把图例当作语义说明：直接关系（实线）/ 派生关系（紫虚线）/ 未配置（灰虚线）。实现的图例是「对象属性 / 未发布」——表达的是**边类型与发布状态**，而不是设计要的**关系性质**。「未配置」这一态（映射向导里用琥珀虚线表达）在设计器里完全缺失。

**N5 · 资源池没有分类与计数**

设计把资源池当作装配进度的仪表盘（类型 6 / 关系 8 / 域 2，未入画布/已入画布各自带计数）。实现只有一个平铺列表，用户无法一眼看出「还有几类资源没装配」。

**N6 · 检查器缺数据属性清单**

设计里检查器是这个模块最实用的部分：选中实体后直接列出它的数据属性（name/level/dept…还有 9 项）。实现只给了机读名、坐标、域归属——**装配时看不到这个类型有什么属性**，而映射阶段恰恰依赖这些属性。

## 4. 五个对象之间的关系与闭环

设计意图的装配链：

```
实体类型 ─┐
关系类型 ─┼─ 装配（本体设计器）→ 本体 ─ 发布 → 冻结版本 ─┬→ 本体导出（Turtle/JSON-LD）
业务域   ─┘                                              ├→ 映射向导（目标本体）
                                                          └→ 抽取 → 图谱 → 证据追溯
```

逐环节实测：

| 环节              | 入口                               | 状态                                                 |
| ----------------- | ---------------------------------- | ---------------------------------------------------- |
| 实体类型 → 设计器 | 资源池「未入画布 → +」             | ✅ 可入画布，画布渲染为节点                          |
| 关系类型 → 设计器 | 同上                               | ✅ 可入画布，画布渲染为边（可点选）                  |
| 业务域 → 设计器   | 同上                               | ⚠️ **可入画布但画布无呈现**（见 N1），且无分区（N2） |
| 本体 → 设计器     | 本体库「设计器」/ `?ontology=<id>` | ✅ 本轮打通                                          |
| 本体 → 发布       | 本体库「发布」/ 设计器顶栏「发布」 | ✅                                                   |
| 本体 → 导出       | 治理 → 本体导出（读发布快照）      | ✅                                                   |
| 本体 → 映射       | 抽取 → 映射向导「目标本体」        | ✅（需已发布）                                       |
| 装配模板 → 本体   | 治理 → 装配模板 → 实例化           | ✅                                                   |
| 设计器 → 校验     | —                                  | ❌ 设计器内无校验入口，装配完不知道能不能发布        |
| 设计器 → AI 辅助  | —                                  | ❌ 全站无 AI 入口                                    |

**一句话**：**「能装配、能发布、能导出」这条主干是通的**（本轮补上本体库与新建入口后闭环完整）；缺的是装配过程中的**质量反馈**（校验、AI 建议、属性清单、分区视图），也就是设计稿里让设计器成为「星图主场」的那部分。

## 5. 优先级建议

**第一批（影响装配正确性）**

1. **N1 + N2 业务域在画布上的呈现**：给域画分区（背景块 + 标题），或至少让入画布的域在画布上有可见载体。当前「已入画布列表里有、画布上没有」是明确的状态不一致。
2. **N6 检查器补数据属性清单**：装配时看不到类型有哪些属性，直接影响后续映射配置。
3. **N3 本体基本信息可编辑**：`PUT /ontologies/{id}` 已有，补入口即可。
4. **设计器内补校验入口（#3）**：装配完能直接看到「8 项校验」的结果，否则用户不知道能否发布。

**第二批（设计一致性）**

5. **N4 图例改回语义三项**（直接关系 / 派生关系 / 未配置），并在画布上真正区分派生边与未配置边。
6. **N5 资源池按类型/关系/域分类 + 计数**。
7. **实体类型列表第四项改「校验违反」**，补业务域筛选与属性数/关系数/更新时间列。
8. **实体类型详情补齐三个空页签 + 继承链可视化 + 校验状态 + 引用面**。
9. **业务域改树形**（域/继承/关系三分离）。

**第三批（设计签名元素）**

10. **AI 辅助入口**（`AI 补全关系` + 检查器里的「应用建议」）——需要产品决策：真做还是修订设计稿。
11. **模板选择器**（`模板：GB/T 48000.3 核心`）。
12. **面包屑带本体名**；关系类型详情页。
