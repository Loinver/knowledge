## 2. 核验环境与纪律

1. **隔离运行**：`pnpm -C web build` 后由后端托管 `web/dist`，使用**独立端口（如 8010）**和**数据库副本**（复制 `server/knowledge.db` 到 `/tmp/kgaudit/`），不影响正在运行的 `make dev`（4000/4010）。核验结束时证明真实库未被写入（对比关键表行数）。
2. **场景数据**：若 `samples/` 不足以覆盖第 4 节的五类场景，允许在 `/tmp/kgaudit/` 下另建**只读场景源库**（SQLite），但不得修改 `samples/`；场景库的建表脚本作为报告附录给出，供后续正式纳入样例库。
3. **全程走界面**：建模、映射、抽取、浏览、追溯必须在浏览器界面完成（Playwright 或手工），API 只用于核对结果与取证。凡是「只能靠调 API / 改库 / 改代码才能完成」的环节，一律判为**闭环断点**。
4. **本机代理**：`curl` 访问 127.0.0.1 加 `--noproxy '*'`。
5. **测试**：先跑 `make lint`、`make test`、`make test-e2e`（在隔离库上），记录通过/失败数量；失败项区分「既有失败」与「本次发现」。
6. **不修复**：发现问题只记录，不顺手修。

## 3. 判定口径

每个核验项必须给出以下之一，并附证据：

| 结论        | 含义                                                               | 证据要求                                   |
| ----------- | ------------------------------------------------------------------ | ------------------------------------------ |
| ✅ 已实现   | 界面可操作、结果正确、刷新后持久、有自动化测试或实测记录           | 截图/DOM 摘录 + API 响应摘录 + `file:line` |
| ⚠️ 部分实现 | 能用但缺字段、缺交互、需绕路或结果不完整                           | 说明缺什么 + 证据                          |
| ❌ 缺失     | 无入口或无实现                                                     | 搜索过的路径/关键字，证明确实没有          |
| 🔌 断点     | 功能存在，但与上下游**接不上**（例如需要手工改库才能进入下一环节） | 断在哪一步、需要什么绕路                   |
| ❔ 未验证   | 受环境限制无法验证（如国标原文不可读、OWL 推理器未接）             | 说明限制，**不得**写成通过                 |

硬约束：

- 校验结果四态 `PASS / VIOLATION / NA / NOT_RUN` 不得失真：没执行的就是 `NOT_RUN`，发现「未执行显示为通过」直接记 P0。
- 版本冻结：本体发布冻结资源版本、映射发布冻结本体版本、图谱版本冻结映射版本；发现上游改版静默影响下游，直接记 P0。
- 计数口径：实体数、三元组数、派生边数、隔离数分开统计；派生边不计入事实数。

## 4. 五类场景：从本体到图谱形态的端到端要求

这五类知识**必须由本体定义、经映射从源库抽取产生**，而不是前端内置或手工录入的演示数据。图谱的展示形态应当由**本体语义**（关系类型的层级性、传递性、对称性、关联实体属性等）驱动选择，而不是按某个 IRI 或表名硬编码。

对每个场景，按「本体 → 源数据 → 映射 → 抽取 → 图谱形态 → 追溯」六列逐格核验，产出**场景矩阵**。

### 4.1 部门层级 / 企业组织架构

| 环节     | 要求                                                                                                                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本体     | 类型：企业、部门、岗位、员工。关系：`下设部门`（部门→部门，自引用，**传递**，与逆关系`隶属上级部门`）、`隶属部门`（员工→部门）、`任职`（带属性关联实体：岗位、任职起止日期、是否主岗）、`直属上级`（员工→员工）。业务域「组织管理」 |
| 源数据   | 部门表含 `parent_id` 自引用外键（至少 4 层、含多棵子树）；员工表外键到部门；任职表带属性（同一员工两段任职）                                                                                                                        |
| 映射     | 自引用外键关系映射；带属性关联表 → 关联实体                                                                                                                                                                                         |
| 抽取     | 层级无环；孤儿部门（父不存在）进入隔离并可定位                                                                                                                                                                                      |
| 图谱形态 | **组织架构树**：企业为根、自上而下、直角折线；逐层折叠/展开；节点显示人数汇总；按部门筛选子树；可切换为「汇报线」视图（员工直属上级链）                                                                                             |
| 追溯     | 任一上下级边 → 部门表行键 + `parent_id` 字段 + 运行批次                                                                                                                                                                             |

### 4.2 股权架构

| 环节     | 要求                                                                                                                                                                                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本体     | 类型：企业、自然人。关系：`持股`（股东→被投资企业，**带属性关联实体**：持股比例、认缴出资额、出资日期、持股方式直接/间接）；逆关系 `被持股`；派生关系 `间接持股`/`实际控制`（由规则推导）。数据属性值域：比例 `xsd:decimal` 且 0～100（或 0～1，需与规则一致） |
| 源数据   | 股东表（股东可为企业或自然人，**多态端点**）；至少三层持股链、一个交叉持股、一个环形持股、一个合计 >100% 的异常样例                                                                                                                                            |
| 映射     | 多态端点（按股东类型字段分别映射到企业/自然人）；比例字段转换与空值策略                                                                                                                                                                                        |
| 抽取     | 比例越界、合计 >100% 由规则命中并进入实例校验报告；派生的 `间接持股` 与直接持股分开计数                                                                                                                                                                        |
| 图谱形态 | **股权穿透图**：以目标企业为中心，**向上**展开股东、**向下**展开对外投资，双向分层树；**边上显示持股比例**；控股（>50%）加粗/高亮；可计算并标出**最终受益人/实际控制人**（穿透比例 = 链上比例乘积）；环形持股有明确提示而非无限展开                            |
| 追溯     | 比例数值 → 股东表行键 + 比例字段 + 转换链；派生边 → 推导规则 + 参与推导的各条直接事实                                                                                                                                                                          |

### 4.3 人物关系

| 环节     | 要求                                                                                                                                                                                                                                   |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本体     | 类型：自然人（员工与股东、法定代表人为同一类型或有 `sameAs` 融合）。关系：`同事`（**对称**，可由同部门派生）、`上下级`、`共同参与项目`（派生，经项目成员关联实体）、`担任法定代表人/高管`（人→企业）、`亲属`（对称，带属性：关系类别） |
| 源数据   | 员工、项目成员（已有 `pm_project_member`）、高管任职、亲属关系表                                                                                                                                                                       |
| 抽取     | 对称关系不重复计为两条事实，也不丢方向信息；同一对人的多种关系分别保留                                                                                                                                                                 |
| 图谱形态 | **以人为中心的关系网络**：力导向或放射布局；按关系类型着色并有图例；同一对节点多条关系分开弯曲（不因视觉去重丢证据）；**两人之间最短关系路径**查找；按关系类型过滤；1/2/N 度展开且有上限与截断提示                                     |
| 追溯     | 派生关系（如同事、共同参与项目）能展开「由哪些直接事实推出」                                                                                                                                                                           |

### 4.4 客商（客户 / 供应商）

| 环节     | 要求                                                                                                                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 本体     | 类型：企业（本企业/外部企业）、客户、供应商（建议建模为企业的**角色**而非独立实体，需核验建模方式与国标一致）。关系：`供货`、`采购`、`交易往来`（带属性关联实体：累计金额、交易笔数、首末交易日期）。业务域「客商管理」 |
| 源数据   | 客户表、供应商表，**同一外部企业既是客户又是供应商**；交易/订单明细表                                                                                                                                                   |
| 映射     | 同一企业从两张表抽取时 IRI 相同（按统一社会信用代码融合），不产生重复节点                                                                                                                                               |
| 图谱形态 | **客商关系图**：本企业居中，左侧上游供应商、右侧下游客户（二分/供应链布局）；边宽或标签表达交易金额；双重角色企业有明显标记；按金额区间、时间窗口筛选                                                                   |
| 追溯     | 节点融合可解释：该节点来自哪几张表的哪几行；金额聚合可展开到明细行                                                                                                                                                      |

### 4.5 合同

| 环节     | 要求                                                                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 本体     | 类型：合同、企业、自然人、项目。关系：`签约方`（合同→企业，**带属性**：甲方/乙方/丙方角色）、`经办人`、`关联项目`（已有中间表 `ct_contract_project`）、`补充协议`（合同→合同） |
| 源数据   | 当前 `ct_contract` **没有签约方字段**，需签约方表或甲乙方外键；补充协议自引用                                                                                                  |
| 图谱形态 | **合同网络**：以合同为中心的星型（签约方/项目/经办人），或以企业为中心反查全部合同；**时间轴视图**按签订日期排布；金额聚合；合同 ↔ 客商图联动（从客商节点跳到相关合同）        |
| 追溯     | 签约方角色、金额、日期 → 合同表/签约方表的行键与字段                                                                                                                           |

### 4.6 通用图谱交互（所有场景都要核）

- 视图切换：同一图谱版本可在第 4.7 节形态目录中的各形态与表格之间切换，切换时**保持**当前图谱版本、选中实体与过滤条件；视图选择依据本体语义给出推荐（第 4.8 节）。
- 带属性关系：关联实体可**折叠为带属性标签的边**（比例、角色、金额），也可展开为节点；当前核验须确认边是否能携带并显示属性。
- 检索与过滤：名称/业务键/IRI 检索；按实体类型、关系类型、**业务域**、时间区间过滤；直接关系实线、派生关系紫虚线且可开关。
- 画布：缩放、平移、拖拽、适应窗口、小地图、选中高亮邻居、导出图片；节点详情抽屉（属性 / 出边 / 入边 / 派生边 / 证据五页签）。
- 版本：选择图谱版本用可读的下拉（运行时间、映射版本、是否当前），而非手输数字 ID；两个图谱版本之间可做差异对比（新增/删除实体与事实）。
- 规模：节点/边上限、截断提示、分页/懒加载；在 ≥1 万实体、≥5 万事实的数据上记录首屏时间与交互帧率，写明当前支持上限。
- 可访问性与主题：键盘可达、焦点可见、明暗主题、窄屏布局、`prefers-reduced-motion`；图例颜色之外有形状/线型区分。
- 双语：切换中英文后图谱控件、图例、提示全部翻译，无裸文本。

### 4.8 形态选择机制（本体驱动，不硬编码）

1. **语义信号 → 推荐形态**：系统读取当前图谱版本所钉住的本体快照，按下表给出推荐，并说明推荐理由。

   | 本体语义信号             | 推荐形态                                       |
   | ------------------------ | ---------------------------------------------- |
   | 自引用 + 传递的关系      | G-01 / G-02 / G-08                             |
   | 关联实体带比例或金额属性 | G-06 / G-07 / G-17 / G-18 / G-03 / G-04        |
   | 对称关系                 | G-10（无向边）                                 |
   | 两个类型之间的多对多关系 | G-13 / G-20                                    |
   | 关联实体端点数 ≥ 3       | G-15                                           |
   | 日期属性或起止区间       | G-21 / G-22 / G-23                             |
   | 行政区划或经纬度属性     | G-25                                           |
   | 所选关系上存在环         | G-09                                           |
   | 同一 IRI 有多个来源      | G-29                                           |
   | 始终可用                 | G-11 / G-12 / G-16 / G-24 / G-26 / G-28 / G-30 |

2. **视图模板可配置**：不改代码，就能为某个本体指定「层级关系 = 下设部门」「度量属性 = 持股比例」「时间属性 = 签订日期」「地理属性 = 注册地」「中心实体类型 = 企业」，保存为视图模板。模板与本体版本绑定，或者自带版本；本体升级后，若模板引用的资源失效，要明确提示，不能静默出错。
3. **换本体仍可用**：改用一个关系命名完全不同的新本体，只要语义信号相同，就应得到同样的推荐。核验时要实际构造一个改名本体来验证，防止实现按 IRI 或表名硬编码。
4. **不适用要说明原因**：形态不可用时（例如缺少日期属性），要说明缺哪种语义、去哪里补，而不是显示一张空白画布。
5. **切换时保持上下文**：在多种形态之间切换时，当前图谱版本、选中实体和过滤条件保持不变。

### 4.9 每种形态的通用验收标准

第 4.7 节中凡是判为已实现的形态，都要同时满足以下各条，否则降为 ⚠️：

- 数据来自所选图谱版本，并且能切换版本；
- 有图例，且图例语义与本体一致（直接/派生、关系类型、度量编码）；
- 超出上限时有截断提示；空态要说明原因；
- 点任意节点或边，都能打开详情和证据（接入 G-26）；
- 可叠加质量层（G-28）；
- 可导出 PNG/SVG 图片和 CSV 数据；
- 键盘可达，焦点可见；支持明暗主题、双语、窄屏；
- 写明规模上限，并在该规模下实测首屏耗时。

## 5. 模块核验清单

编号规则 `V-<模块>-<序号>`，报告中逐项回填结论与证据。对应需求编号放在括号里。

### 5.1 实体类型（H-11）

- V-ET-01 列表：统计条（总数/已发布/草稿/校验违反）、业务域与状态筛选、表格/卡片/图谱视图、属性数/关系数/更新时间列、服务端分页与远程搜索（第 201 条之后可发现）。
- V-ET-02 详情六页签：基本信息 / 数据属性 / 类型层级 / 关联关系 / 规则 / 引用与版本，均有真实数据而非占位。
- V-ET-03 数据属性：IRI、名称、双语标签、定义、数据类型（五类基本类型 + 日期）、枚举字典显式引用、可空、默认值、基数、约束、**来源条款**列。
- V-ET-04 继承：父类型选择、继承链可视化、环路拒绝、子类型继承父属性的展示。
- V-ET-05 IRI 治理（H-03）：命名空间注册、IRI 唯一性、**更名影响面扫描**并同步关系端点、域成员、本体引用、映射。
- V-ET-06 状态机与并发（H-02）：草稿→发布→新版本；`If-Match`/`If-Edit-Match` 防覆盖（两个标签页同时编辑，后保存者被拒）。

### 5.2 关系类型（H-12）

- V-RT-01 定义域/值域（含多端点「并集 vs 交集」表达）、基数及约束方向、逆关系、OWL 特征（功能性/反函数/对称/非对称/传递/自反）及兼容性校验（如对称 + 非对称互斥）。
- V-RT-02 带属性关系：开关后生成**关联实体 + 端点角色 + 属性清单**；同一对实体两条关系分别保存（A06）。
- V-RT-03 自引用关系（部门→部门、合同→合同）、多态端点（股东可为企业或自然人）能否表达。
- V-RT-04 关系详情页、卡片迷你图、搜索、发布、版本历史、被引用处。
- V-RT-05 **图谱展示语义**：关系类型上是否有（或可推导出）层级/持股/对称/交易等语义，供图谱选择视图形态；没有则记录为图谱场景视图的上游缺口。

### 5.3 业务域（H-10）

- V-BD-01 域树（父子分层、环路拒绝）、成员清单、**维护责任域唯一**、跨域引用。
- V-BD-02 发布前四项检查：成员存在性、版本可用、依赖完整、循环引用。
- V-BD-03 域 ≠ 继承 ≠ 业务关系三分离（数据模型、操作入口、导出语义）（A02）。
- V-BD-04 为五类场景各建业务域（组织、股权、客商、合同、人员），同一类型（企业、自然人）多域引用指向同一资源（A01）。

### 5.4 本体（H-13 / M-02 / M-04 / M-06 / M-07）

- V-ON-01 本体库：新建（可选装配模板，模板来源必填）、基本信息编辑、发布、版本列表、另存为模板。
- V-ON-02 装配：引用业务域/单类型/关系按 IRI 去重；**相同资源不兼容版本显式冲突**；发布冻结全部资源版本（A04）。
- V-ON-03 核心模板核对（M-02）：GB/T 48000.3 第 6 章核心类型 + 表 1 核心对象属性逐项 `PRESENT / MISSING / KIND_MISMATCH / ENTERPRISE_EXTENSION`；企业扩展与标准核心分别标注（A16）。

### 5.5 本体建模 · 设计器（H-13）

- V-DS-01 全页画布：资源池按类型/关系/域分组计数、拖入画布、业务域分区、自动布局、缩放适应；拖拽只改布局不产生语义版本（A17）。
- V-DS-02 检查器：标签、状态、IRI、数据属性清单、域归属；点关系边可看定义域/值域/基数/特征。
- V-DS-03 **在画布上直接建模**：新建类型、连线建关系、编辑属性，而不是只能从库里拖入已有资源（核验是否支持，若不支持记录对建模效率的影响）。

### 5.6 规则（M-01 / H-50 / H-51）

- V-RU-01 规则资产字段：标识、双语名称、分类、来源（`STANDARD` 标准条款 / `ENTERPRISE` 企业规则）及依据、作用类型、严重程度、OWL/SHACL 表达、执行方式、正反例。
- V-RU-02 正反例检查返回真实 pySHACL 报告；规则可挂入本体草稿并随发布冻结。
- V-RU-03 **规则真正参与抽取**：抽取第三阶段执行规则，命中结果进入实例层校验报告与隔离清单，并能从命中项定位到焦点节点和源行。
- V-RU-04 场景规则各至少一条并实测：部门层级无环、持股比例 0～100 且合计 ≤100%、合同签约方至少两方、同一企业信用代码唯一、日期词法（`YYYYMMDD` vs `xsd:date`）。
- V-RU-05 **推理/派生规则**：能否定义「间接持股 = 持股链」「同事 = 同部门」这类派生关系并在抽取时生成派生边（L-08）。若只能校验不能推导，明确记录。
- V-RU-06 标准条款资料（M-03）与四项解释差异记录；规则来源在界面与报告中始终可见。

### 5.7 知识抽取（H-20～H-22、H-30～H-33、M-08/M-09）

- V-EX-01 数据源：凭据仅后端持有且加密、测试连接、只读强制、超时；元数据四级下钻、结构快照与变更识别、表被哪些映射引用；受限样例预览。
- V-EX-02 映射向导 5 步 + 图谱/表格双视图；未配置项在图上可见；字段四列（目标属性/源字段/转换/空值策略）+ 样例实算。
- V-EX-03 关系映射三模式（外键 / 中间表 / 带属性关联表）+ **自引用外键** + **多态端点** + **多表抽同一类型并按业务键融合**（A10）。
- V-EX-04 抽取四阶段（实体 → 关系 → 规则 → 隔离）；幂等（重跑 IRI 集合、关系数、隔离数完全一致）；零产出判失败；失败不覆盖当前结果集；可切回历史成功版本（A13、A20）。

### 5.9 知识追溯（H-42）
