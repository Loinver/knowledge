# 知识库、搜索问答、账户与系统管理

核验日期：2026-11-26；适用 `9222236` 加当前未提交工作区。功能和验证边界见[知识与系统台账](../product/features-knowledge-system.md)、[核验记录](../maintenance/verification-2026-11-26.md)。以下“示例制度库”“示例员工手册”等均为虚构示例。

<a id="kno"></a>

## 一、把文档变成可查询知识（KNO-001～003）

**解决问题**：将制度、说明和CSV文本放在一个可追溯的检索上下文中。所有登录用户可读；EDITOR/ADMIN负责内容。先确认资料适合在当前全局角色范围共享，知识库不是个人私有空间。

1. 进入「知识库」，按名称和活动/归档状态查找已有库；新建“示例制度库”，填写范围说明，避免重复建库。
2. 打开库详情，上传UTF-8 TXT、Markdown或CSV。示例内容可写：“示例星河公司员工借阅设备须登记归还日期。”文件需小于等于2MiB；PDF、Word和扫描件不支持。
3. 在文档列表与任务详情观察排队、解析、索引和最终状态。等待出现可用活动索引，再进入搜索。上传返回并不意味着已处理完成。
4. 打开文档查看片段数、解析警告、模型版本和任务原因。CSV部分解析时可能只有有效前段可检索；PARTIAL不等于全部成功。
5. 来源文本不会被重处理修改。模型或解析环境改变时可重处理；要修正原文，应上传修正后的文件并按保留要求归档旧文档。相同字节内容在同库去重，换文件名不会产生新内容版本。
6. 暂停使用时归档文档或库；需要时恢复。遇到修订冲突先刷新核对，不能直接覆盖他人更新。归档不物理删除文件、历史索引和证据，不作为数据销毁或访问隔离手段。

**结果**：原文与处理记录保留，成功索引可被查询；重处理失败保留之前成功的活动索引。无向量模型时仍可形成关键词索引，不能把“未配置向量”显示为语义检索可用。

| 限制         | 当前值与处理                                                               |
| ------------ | -------------------------------------------------------------------------- |
| 单文件       | 2MiB；仅允许的UTF-8文本格式，不能改扩展名冒充                              |
| 单库文档数   | 100，包含已归档文档；归档不释放此额度                                      |
| 单文档片段   | 最多2000，每段最多800字符；超限需在来源侧合理拆分                          |
| 单库活动片段 | 最多10000；恢复或发布索引也会检查                                          |
| 后台处理     | 应用worker需开启；任务持久化，进程租约与心跳决定归属，仍需实际部署恢复验收 |

**常见失败**：QUEUED持续不动时核对 `KG_KNOWLEDGE_WORKERS_ENABLED` 与服务日志；非法UTF-8需要转换后重新上传，重复重试同一原文件不会修复编码；模型网络失败先检查默认配置和外部连通性。详见[故障排查](../operations/troubleshooting.md)。

## 二、搜索与证据摘录问答（KNO-004～005）

**解决问题**：找到原文中能支持业务问题的内容。VIEWER也可使用；需要活动知识库及可用索引。

1. 从知识库进入搜索，输入“设备归还日期”等具体业务词。先使用关键词模式建立可复核基线；搜索仅针对当前知识库。
2. 有可用EMBEDDING默认服务与当前向量后可选语义模式，混合模式结合关键词与语义排序。查看覆盖提示，不把部分文档未索引误解为“文档里没有”。
3. 从命中打开证据，核对文档、段落/行号或CSV记录、原文片段和历史状态。搜索分数是排序依据，不是事实置信度或合规通过率。
4. 需要问答时输入具体问题并执行。CHAT服务从命中证据选择连续原文摘录；界面返回引用或“证据不足”。逐项点开来源再采用结论。
5. 若显示能力不可用，联系管理员检查对应默认模型；若显示错误，先解决服务或索引问题，不能把错误当空结果。

**结果**：得到可定位的原文片段或受引用约束的摘录答案。问答不提供脱离证据的自由生成正文，也不是可自动执行业务操作的Agent。

**常见失败**：向量STALE时重新处理相关文档；无命中时缩小/调整查询并检查活动状态；引用校验失败或模型协议错误需要查服务日志，不能通过忽略引用来生成答案。外部模型实际效果本轮未验收。

## 三、补充图事实的文档证据（KNO-006）

**解决问题**：给已存在的图事实增加制度说明或原文上下文。读证据只需登录；建立关联需EDITOR/ADMIN。

1. 在搜索证据中确认片段属于当前活动文档，不是历史或已归档片段。
2. 打开图谱关联操作，明确选择/输入结果集、实体IRI和可选事实编号；事实必须属于同一结果集且主体与所选实体一致。
3. 确认关联后，从图谱实体/事实的文档证据查看该片段，保留版本上下文。

**结果**：固定版本的人工文档引用，不会生成新图事实，也不改变源表抽取证据。当前查询最多返回50条关联引用；没有对应的关联删除操作。

**常见失败**：目标不存在或版本不符时回图谱核对结果集；片段已归档/成为历史时查看新索引，不强行关联。修订冲突需要重取文档状态。归档资料不自动把已存在事实从图谱删除。

## 四、登录、资料与密码（ACC-001～003）

**解决问题**：准确找到当前环境的身份，维护自身资料和安全访问。首次管理员由实施人员按[部署指南](../operations/deployment.md)创建；后续账户由ADMIN发放。

1. 确认访问的是开发、正式部署还是隔离预览。使用该库对应用户名/邮箱与口令登录；不存在通用 `admin` 密码。
2. 从账户菜单进入个人资料，更改显示名与头像URL。当前功能不提供个人自行改角色或组织授权。
3. 记得旧密码时，在「账号安全」提交旧密码和新密码。口令规则以表单/公开配置为准；当前最短8字符。成功后当前访问令牌保留，其他令牌被撤销，刷新时可能要求重新登录。
4. 忘记密码时，请另一位管理员在用户管理为你签发一次性链接，经安全渠道转交。打开链接输入新密码，成功后旧会话失效；过期或已用链接需要重新签发。
5. 离开共享设备时退出登录。会话过期、用户禁用和密码重置可能导致重新认证，不应手改浏览器令牌恢复权限。

**结果**：个人资料和密码更新有明确反馈，身份与环境对应。公开注册默认关闭；开启时新用户为VIEWER。

**常见失败**：登录失败先核对环境、账号状态与初始化口令，重复失败可能触发限流。`make seed-admin`遇到已有账号会拒绝，不能用它找回密码。没有邮件服务，默认找回入口不可用；唯一管理员失去访问且无其他管理员时，没有产品内自助恢复功能，应由实施人员走受控恢复流程，不能为此删除数据库。

## 五、用户和固定角色（SYS-001～002）

**解决问题**：发放账号、调整职责、停用不再使用的账户。仅ADMIN。

1. 进入「系统管理 → 用户管理」，搜索现有用户，核对用户名、邮箱、角色与状态。
2. 新建用户并选择ADMIN/EDITOR/VIEWER；只读使用者选VIEWER，内容维护者选EDITOR。安全交付初始凭据，不复制进工单或文档。
3. 根据职责调整角色或启用/禁用。禁用会撤销会话；用户恢复启用后重新登录。
4. 他人忘记密码时签发一次性重置链接。自己的改密使用账号安全，系统不允许自降级、自禁用或给自己签发此类链接。
5. 进入角色页查看固定角色说明与成员数。该页只读，没有角色创建/删除或在线权限配置。

**结果**：角色与账号状态生效。当前无用户删除、组织树或用户批量导入；详细权限与只读POST例外见[权限表](roles-permissions.md)。

## 六、配置模型与默认能力（SYS-003）

**解决问题**：让建模辅助、语义检索和摘录问答使用明确的服务。仅ADMIN；先准备被允许使用的协议兼容模型服务。

1. 在「系统管理 → AI模型」新建配置，填写名称、CHAT或EMBEDDING能力、协议base URL、模型名、版本、超时与API Key。
2. 保存后检查启用状态，再为对应能力显式选择默认。CHAT与EMBEDDING分别设置；保存或设默认不会测试远程服务。
3. 协议客户端会追加 `chat/completions` 或 `embeddings`；填写兼容基础路径，避免把完整调用地址再次重复拼接。
4. 编辑时留空密钥保留原值，替换与清除是明确操作；换URL origin时必须替换或清除密钥。平台只显示是否有密钥/掩码，不能读回明文。
5. 更换向量模型或模型版本后检查旧向量状态并重处理。处理中配置变化会阻止错误的新索引发布，保留之前成功索引。
6. 禁用或删除当前默认会清空默认选择；需要继续使用相关能力时另选可用配置。用受控样例执行对应业务操作，验证连通性与输出质量。

**结果**：运行时能力使用数据库中的默认模型配置。旧 `KG_LLM_*` / `KG_EMBEDDING_*`环境变量不能替代当前管理入口。解密密钥必须稳定保管，见[配置说明](../operations/configuration.md)。

**常见失败**：修订冲突时刷新，服务超时检查网络与超时设置，协议或模型名错误核对部署参数；不能以配置保存成功宣称模型可用。真实模型与该页写操作本轮未验收。

## 七、调查账号和资产变化（SYS-004）

**解决问题**：识别谁在何时对什么对象做了何种变更，查找失败与版本上下文。仅ADMIN，审计列表只读。

1. 进入审计日志，选择账号审计或业务资产审计。
2. 按页面提供的操作者、动作、结果、对象与时间等条件查找；需要时用对象ID和关联编号缩小范围。
3. 对照操作前后版本、错误码与时间，再进入对应功能查看当前对象。当前详情与历史审计版本不同并不一定异常。
4. 记录必要上下文供排查，不粘贴真实密码、密钥或源数据；失败结果不应改写为成功。

**结果**：得到已覆盖事件的调查依据。账号与业务资产审计不是所有读取、知识文档和模型配置的统一全量审计；当前没有审计认证、不可篡改存储或自动留存清理承诺。
