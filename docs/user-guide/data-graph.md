# 从业务数据到图谱与证据

核验日期：2026-11-26；基于 `9222236` 与当前未提交工作区。示例使用虚构企业和员工。功能编号、源码与测试见[数据图谱台账](../product/features-data-graph.md)。

<a id="dat"></a>

## 1. 接入只读业务数据（DAT-001～003）

**解决问题**：让建模人员看到源结构和样例，明确字段含义。维护者需要EDITOR或ADMIN；VIEWER可查看目录与只读样例。

准备一个与平台元数据库分离的业务库。首次练习使用[样例说明](../../samples/README.md)生成的隔离源库，记下后端机器上的绝对文件路径。不要把 `server/knowledge.db` 作为数据源。

1. 进入「数据接入 → 数据源」，新建连接，填写名称、类型与连接参数。SQLite填写后端可访问路径；远程连接填写对应主机、端口、库及只读账号。
2. 做连接测试；区分临时连接测试与已保存连接的状态测试。保存成功后再进入数据目录。
3. 选择数据源并采集元数据，展开schema与表，核对字段类型、主键、外键和可空性。
4. 在目录内查看有限实时样例；需要更多样例时进入预览页，明确源、表和偏移。记录数与截断提示不是全库统计。
5. 源结构改变时重新采集，比较快照与引用影响，再调整映射。

**结果**：一个可访问的连接和可用于映射的结构快照。样例读取不修改源数据，也不作为抽取结果保存。

**失败处理**：连接失败先检查后端网络/路径、驱动和只读权限。PG源与MySQL源所需驱动并未完整包含在默认依赖中，详见[部署说明](../operations/deployment.md)。删除被元数据、任务或证据引用的数据源会被拒绝，应保留来源链。

<a id="map"></a>

## 2. 配置、预览并发布映射（MAP-001～003）

**解决问题**：把源表字段转换为明确的业务对象与关系。EDITOR/ADMIN操作，先准备已发布本体和源结构。

映射工作台按步骤组织上下文。以下以企业与员工为例，具体字段名取自当前源目录：

1. 新建映射并选择目标本体与数据源。检查选择的是预期发布版本，给映射填写可识别名称。
2. 将 `enterprise` 表映射为企业类型，将 `hr_employee` 映射为员工类型。以源主键 `id` 构造稳定身份；把 `name` 映射到目标名称属性。根据业务为每个字段选择原值、模板、日期、枚举或小数转换，以及必填、允许空、默认或跳过策略。
3. 员工到企业使用外键关系：`hr_employee.enterprise_id → enterprise.id`。纯中间表使用JUNCTION；包含金额、角色、参与时间等自身属性的关联表使用ASSOCIATIVE并保留每条关联记录身份。
4. 多表同类实体需要业务键融合时，选择共同稳定业务键并明确来源优先级、空值和冲突策略。先检查业务键唯一性与取值格式，不能依赖表遍历顺序决定结果。
5. 保存草稿，运行编译预览，检查生成的实体、关系、属性和异常摘要。预览会写入平台预览记录，VIEWER不能执行。
6. 确认后发布映射。记录生成的映射修订和固定的本体版本，后续运行使用该已发布修订。修改草稿不会自动替换历史修订。

AI辅助可根据结构提出候选映射，需管理员先配置可用CHAT模型。候选经人工逐条确认后进入草稿，仍需保存、预览与发布。文本事实候选仅审阅，不自动写入正式图谱。

**结果**：可重现的已发布映射。预览通过只说明样例条件成立，不保证所有源记录满足约束。

**失败处理**：修订冲突时重新读取对象，保留输入并核对差异；字段不存在先采集结构；目标类型或属性冲突先检查本体冻结版本。删除映射会涉及其草稿、历史修订与预览，应先核查运行引用与保留要求；不要把删除当作撤销发布。

<a id="run"></a>

## 3. 执行、取消与定位异常（RUN-001～003）

**解决问题**：把映射应用到真实数据，判断本次运行产出是否可用。EDITOR/ADMIN发起，所有已登录用户可读运行记录。

1. 在运行或任务入口选择发布映射修订、数据源和实体namespace。
2. 立即执行，或在任务页面指定一次延后时间。任务从PENDING进入RUNNING，再成为SUCCESS、PARTIAL、FAILED或CANCELLED；一次延后执行不是周期cron任务。
3. 运行期间查看阶段与进度。待执行任务可直接取消；运行中取消请求在阶段边界协作生效，不代表立刻终止数据库语句。
4. 结束后检查实体、关系、校验、隔离记录及错误；不要只看一个成功标签。必要时下载运行报告，保留其冻结版本清单。
5. 检查是否生成了可发布结果集，以及当前结果集是否已切换。失败或零产出不能把上一成功结果替换为空结果。

**增量使用前提**：当前实现面向不可变、仅追加数据，要求整数主键和整数递增水位，并绑定可信成功基线。业务键融合、已有行更新/删除、某些复杂端点不支持。不是任意时间字段同步，也不是CDC；不满足条件时选择全量方案或重新评估映射。

**失败处理**：先从隔离原因和具体规则定位到源记录，修改配置或源数据后新建运行。需要追溯旧结果时保持其版本上下文。后台抽取为进程内执行池和懒启动调度，重启恢复与多副本取消没有生产验收，不要把任务显示为PENDING理解为有外部可靠队列保证。

<a id="grf"></a>

## 4. 探索图谱并解释事实（GRF-001～004）

**解决问题**：理解实体之间的关系，确认一条事实来自哪里。需要已有可用结果集，所有登录角色可读。

1. 在图谱工作区明确选择结果集。按实体搜索定位中心，选择1度或2度邻域，按类型与派生边过滤。
2. 选择适合任务的布局和视图；节点/边上选择对象，属性面板显示当前选择上下文。展开关系后核对是否达到节点或边上限。
3. 普通滚轮平移，Ctrl/⌘+滚轮或按钮缩放；需要更多面积时进入焦点模式。过滤不会删除事实，保存布局/视图也不会改变业务断言。
4. 进入实体列表和详情，查看属性、关系与来源贡献。选择具体事实进入证据页，核对源连接、表、行键、字段、运行及冻结映射/本体版本。
5. 业务键融合时查看候选值、冲突、采用策略和各来源行，不能只根据合并后的一个标签推断来源一致。
6. 从来源行反向查询受影响事实；需要分析历史差异时选择两个结果集。EDITOR/ADMIN可将符合条件的历史结果设为当前，切换的是全局指针。
7. 保存视图模板时明确绑定本体版本。过期或不适用模板不能直接套用，图谱视图模板与语义装配模板不是同一对象。

**结果**：能够说明“看的是哪个结果集、哪个对象、哪条事实、哪个来源、依据哪个冻结版本”。人工关联知识文档可以增加可读上下文，但不替代抽取证据。

**失败处理**：空画布先核对结果集和筛选；视图上限提示出现时缩小范围，不把截断当全图。源库改变后历史证据仍按当时记录解释，当前样例与历史值不一致不一定是渲染错误。需要修正事实时回到映射或来源执行新运行，保留旧版本用于比较。
