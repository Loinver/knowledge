# 快速入门：从企业与员工数据到可追溯图谱

核验日期：2026-11-26；适用 `9222236` 加当前未提交工作区。以下名称、网址和数据均为模拟示例；应在隔离练习环境完成。真实项目使用前先评估[能力限制](../product/limitations.md)。

目标：建立“员工就职于企业”的模型，读取样例库，形成一个可查询结果集，并追溯一条关系的来源。需要ADMIN或EDITOR；第一次部署先由ADMIN创建编辑账号。

## 1. 初始化并登录

按[安装说明](../operations/deployment.md)准备Node、pnpm和Python，在仓库根目录运行 `make install`、`make seed-admin`、`make dev`。保存初始化时生成的口令，用创建的账号登录 `http://127.0.0.1:4010/`。

如果正在使用别人提供的预览地址，先确认该预览的独立账号，不要直接套用开发库的admin口令。界面默认关闭公开注册。

## 2. 准备隔离样例源库

从仓库根目录运行以下命令，创建新的临时样例库并输出其绝对路径，不覆盖任何已有数据库：

```sh
python3 - <<'PY'
from pathlib import Path
import sqlite3
import tempfile

folder = Path(tempfile.mkdtemp(prefix='knowledge-training-'))
source = folder / 'enterprise-source.sqlite'
with sqlite3.connect(source) as db:
    db.executescript(Path('samples/seed.sql').read_text())
print(source)
PY
```

这个路径必须对后端进程可见。容器或远程部署需使用后端机器的挂载路径，不能填本机浏览器的文件路径。

## 3. 建立并发布语义资产

进入「语义资产」。建议每次练习使用不同前缀，避免与已有资产重名。

| 对象         | 示例内容                                              | 要点                                               |
| ------------ | ----------------------------------------------------- | -------------------------------------------------- |
| 命名空间     | 前缀 `training`；IRI `https://example.org/training/`  | 地址是标识符，不需要在浏览器打开                   |
| 企业实体类型 | 机读名 `TrainingEnterprise`；中文名“练习企业”         | 在详情添加属性 `Name`，类型string，中文名“名称”    |
| 员工实体类型 | 机读名 `TrainingEmployee`；中文名“练习员工”           | 添加同样的 `Name` 属性；名称输入以当前表单规则为准 |
| 任职关系     | 机读名 `TrainingWorksFor`；中文名“练习就职于”         | 定义域为员工，值域为企业；本练习不启用关联属性     |
| 业务域       | 机读名 `TrainingDomain`；IRI `urn:knowledge:training` | 将两个类型和关系加入业务域                         |

保存并发布实体类型，再创建/发布关系类型；添加业务域成员时选择准确的已发布版本，然后发布业务域。每步检查页面状态，不把保存草稿当成发布。

## 4. 装配本体并检查

进入「本体建模 → 本体库」，建立 `TrainingOntology`，例如使用IRI `https://example.org/training/ontology/`。在设计器或装配入口加入业务域的明确发布版本，或直接选择两个实体类型和任职关系。

核对端点、属性和成员版本。执行校验并查看四态报告：违反项定位到具体对象；未执行项如实保留并判断其影响，不能改显示为通过。满足当前发布条件后发布本体，记录发布修订。工作区可能同时显示“最近发布版本”和“编辑版本”，二者不同。

具体表单、历史和AI建模见[建模与治理指南](modeling-governance.md)。

## 5. 接入样例并配置映射

进入「数据接入 → 数据源」，新建SQLite连接，填入第2步输出的源库绝对路径。连接测试通过后采集元数据，在目录中检查 `enterprise` 与 `hr_employee`。

进入映射工作台，选择练习本体和样例数据源，按以下配置建立草稿：

| 源                               | 目标                 | 身份与字段                           |
| -------------------------------- | -------------------- | ------------------------------------ |
| `main.enterprise`                | `TrainingEnterprise` | 主键 `id`；`name` → `Name`；原值转换 |
| `main.hr_employee`               | `TrainingEmployee`   | 主键 `id`；`name` → `Name`；原值转换 |
| `hr_employee.enterprise_id` 外键 | `TrainingWorksFor`   | 员工 → 企业；引用 `enterprise.id`    |

本练习先使用全量与主键身份，不配置业务键融合和增量水位。保存草稿，编译预览，查看实体和关系是否符合预期，再发布映射。步骤说明见[映射操作](data-graph.md#map)。

## 6. 执行并确认结果

从运行/任务入口选择已发布映射修订、样例数据源和namespace，例如 `https://example.org/training/instances/`，执行全量抽取。

查看运行状态、计数、隔离和校验结果。样例库含用于测试的异常数据，不能承诺每次练习都是零隔离；应根据具体原因解释PARTIAL或FAILED。确认可用结果集已经产生，失败时当前成功结果不能被覆盖。

## 7. 在图谱中验证一条关系

进入图谱工作区选择刚才的结果集，搜索一位员工并展开企业关系。选中关系或进入实体详情，打开证据，记录：结果集编号、事实、源表、行键、字段、运行编号和冻结映射版本。

预期能够解释“这个员工为何与这个企业关联”。若画布为空，先检查结果集、中心对象和过滤；达到展示上限时缩小范围。需要修正时更新来源/映射并新建运行，比较历史结果，不直接改写旧事实。

## 8. 可选：增加文档知识上下文

在知识库新建“练习制度库”，上传虚构UTF-8 TXT或Markdown文件。等待处理完成，先用关键词检索并打开原文片段；不配置模型也能完成这一步。需要语义检索或证据摘录问答时，再由管理员配置并验证对应默认模型。

将检索片段人工关联到已有图事实时确认结果集版本。人工关联是补充阅读证据，不自动变成关系抽取的来源。详见[知识库指南](knowledge-system.md)。

## 完成检查

- 能区分类型定义与实体实例、本体发布版本与工作区编辑版本。
- 能找到映射冻结版本、本次运行、当前图谱结果集。
- 能从一条关系追溯到样例表与来源行。
- 能解释至少一个校验或隔离状态，而不是只查看“通过”。
- 确认练习数据位于隔离环境，未连接开发元库或真实业务写库。
