## 角色与工作顺序

VIEWER 可查看大多数资产、冻结历史及已有报告；EDITOR/ADMIN 才能保存资产、发布本体、运行持久校验、导入预览/恢复或生成 AI 候选。VIEWER 可以试跑保存的规则，这是特定逻辑只读 POST 例外。菜单可见不等于写操作获准；后端权限决定最终结果。

通常先登记命名空间和字典，再定义实体/关系及域，发布资源后装配本体，核验与发布，最后导出或交给下游。模板可复用固定成员；AI 只能辅助有证据、经人工确认的工作内容。冻结版查看、本体工作内容、资源撤回编辑三种状态不能混为一谈。

## SEM-001 业务域树与成员治理

**问题**：如何把员工、部门类型归到组织管理业务域，同时允许其他域复用？

**角色**：业务域负责人、建模编辑者。

**前置**：EDITOR 或 ADMIN；已有类型。只读角色可以查看域树和成员；发布前先发布成员。

**操作**：

1. 在“业务域”创建 `Organization`，中文名“组织管理”，IRI `urn:example:domain:organization`（模拟）。
2. 选择该域，添加 Employee、Department 为普通成员；在其他域复用时可选引用成员（模拟）。页面未提供维护责任域设置，若需要唯一责任治理须按 API owner_domain_id 契约单独配置。
3. 需要层级时选择父域；执行发布前检查，修正成员缺失、未发布或跨域循环问题，再发布。

**结果**：域产生发布修订，成员版本被固定；日后改成员需要重新发布才形成新域快照。

**失败处理**：维护责任域冲突仅在 API 指定 owner_domain_id 时检查；需统一责任域再提交。循环时调整父域/引用。版本冲突先刷新当前域再重做。删除父域需先处理子域；删除会移除该域历史，先确认业务留存需求。

## SEM-002 命名空间登记与保护

**问题**：如何让组织模型的类型拥有稳定、可共享的标识？

**角色**：语义资产管理员、建模编辑者。

**前置**：EDITOR/ADMIN；准备专用前缀和带尾部分隔符的命名空间 IRI。

**操作**：

1. 在“命名空间”登记前缀 `org` 和 IRI `https://example.org/org/`，显示名“组织模型”（模拟）。
2. 创建类型时选择该命名空间，例如 `Employee` 的 IRI 为 `https://example.org/org/Employee`。
3. 查看资源计数后决定是否删除；只对无资源使用且未保护的命名空间操作。

**结果**：命名空间可在实体、关系建模时复用，页面显示保护标志和使用数量。

**失败处理**：重复前缀/IRI 改为新的合法组合；受保护或仍被使用时删除被拒绝。已有命名空间没有直接编辑入口，不能把换前缀当成普通改名。

## SEM-003 实体类型、属性、继承与详情追溯

**问题**：如何定义员工的工号、入职日期和在职状态，并查看它被谁使用？

**角色**：领域建模者、数据治理人员。

**前置**：EDITOR/ADMIN；已有 `org` 命名空间；若使用枚举，先建立字典及版本。

**操作**：

1. 在“实体类型”创建 `Employee`，中文标签“员工”（模拟），选择组织命名空间。
2. 打开详情，补充定义；需要继承时选择父类型，避免自身或循环继承。
3. 添加 `employeeNo`（string，非空）、`hireDate`（date）、`employmentStatus`（enum，选择字典与明确修订）（模拟），检查默认值和约束。
4. 发布后查看关联关系、规则、引用与版本；演进时先撤回再编辑，完成后重新发布。

**结果**：类型和属性有稳定 IRI，发布产生不可变快照；已发布本体仍引用原来版本。

**失败处理**：409 冲突先刷新详情，不能盲目重发旧属性整表。属性默认值不在枚举中或数值/基数范围非法时修改输入。发布过的类型即使撤回也不能物理删除；外部引用亦会阻止删除。

## SEM-004 关系类型、端点及关联实体建模

**问题**：如何表达员工隶属部门，以及员工参与项目时的起止时间？

**角色**：领域建模者。

**前置**：EDITOR/ADMIN；已经有 Employee、Department、Project 实体类型（模拟）。

**操作**：

1. 创建 `BelongsTo`（模拟），设置员工→部门端点，给每侧基数方向填写业务说明。
2. 需要“参与项目”这种每次关联有独立属性的关系时，在创建 `ParticipatesIn` 时启用关系属性，加入开始日期、结束日期（模拟）。
3. 保存后打开详情核对端点、角色、OWL 特征和属性，再发布。
4. 草稿编辑入口会回到关系列表编辑抽屉；普通关系已发布后可撤回再编辑。

**结果**：普通关系保存对象属性；启用属性的关系伴生 ASSOC 资源，供后续映射承载每次关联的字段。

**失败处理**：关系模式不能事后切换，并集/交集不支持。遇到特征组合拒绝，按实际支持配置重新设计，不能把提示解释为实例不一致。已发布 ASSOC 的属性编辑受限，保留现有版本并交建模负责人评估新关系版本方案。

## SEM-005 版本化枚举字典与引用影响

**问题**：如何统一在职状态，又不改变已发布员工模型的旧含义？

**角色**：数据标准维护者、建模者。

**前置**：EDITOR/ADMIN；取值采用业务码；查看和查历史可由 VIEWER 完成。

**操作**：

1. 创建 `EmploymentStatus`，条目 `ACTIVE`/“在职”、`LEFT`/“离职”（模拟）。
2. 在员工属性中选择该字典及修订 1，默认值填 `ACTIVE`（模拟）。
3. 后续新增状态时保存字典形成新版；查看“历史”和“引用”中字段固定的版本与最新版本。
4. 需升级某字段时显式编辑其字典修订，再发布类型/本体。

**结果**：新字典修订可复用，旧字段与已发布快照继续使用原字典定义。

**失败处理**：默认值不在当前选择的修订中则调整值或修订。409 刷新字典后重新编辑。当前或历史引用存在时不可删；仅清空当前属性不保证解除历史保护。

## SEM-006 装配模板与核心成员核对

**问题**：如何复用组织模型的固定类型集合，核对有没有遗漏核心成员？

**角色**：标准维护者、建模者。

**前置**：EDITOR/ADMIN；资源已发布且有可选修订；核心检查前建立标准条款索引和业务要求清单。

**操作**：

1. 在“装配模板”选择 Employee、Department 及真实发布版本，建立“组织基础模板”（模拟）。
2. 也可选择一个发布本体及版本生成模板；内置模板需要先复制再自定义。
3. 打开核心检查，录入期望的机读名、资源种类及条款 ID，查看缺失/种类不匹配/扩展项。
4. 实例化前预览模板版本与成员，填写新本体名称、IRI、双语元数据并确认。

**结果**：获得引用固定资源版本的本体工作内容；核心检查显示当前要求清单与模板成员的匹配情况。

**失败处理**：资源版本缺失先修正模板。内置模板改删被拒绝时复制。并发冲突重新读取最新模板再预览。没有要求清单的“全核心存在”不能作为标准验收证据。

## SEM-007 IRI 辅助与同义词元数据 API

**问题**：集成方如何检查命名合法性、写入“员工/职员”别名？

**角色**：接口集成者、语义建模者。

**前置**：登录令牌；写别名需 EDITOR/ADMIN，并按对应资源版本契约传参。该能力没有独立菜单。

**操作**：

1. 使用 IRI validate 查询 name 与 namespace；build 端点当前接受 GET JSON 请求体，集成时按生成契约实现，不按普通查询拼接猜测。
2. 为 Employee 写 synonyms，例如 [{"language":"zh-CN","text":"职员"}]（模拟）；其他既有元数据保持原值。
3. 使用 impact 看直接资源引用，再结合详情的域、本体、规则、版本信息评估影响。

**结果**：获得合法性布尔值、构建 IRI 或直接引用列表；别名保留为带语言的元数据。

**失败处理**：别名必须合法且同语言不重复；null 不代表清空。impact 空数组不证明无下游依赖；改名必须另核查完整引用和发布状态。

## ONT-001 本体工作内容与资源装配

**问题**：如何把组织管理类型和规则装配为可交付本体？

**角色**：本体负责人、建模者。

**前置**：EDITOR/ADMIN；已有资源；按业务域批量添加需有发布域版本；发布本体前先发布资源。

**操作**：

1. 在“本体库”创建 `OrganizationModel`，中文名“组织管理本体”，IRI `urn:example:ontology:organization`（模拟）。
2. 打开设计器，选择该本体；从资源池添加 Employee、Department、BelongsTo（模拟）。
3. 按业务域添加时使用该域的发布成员集合；已有相同资源和版本可复用，冲突时不能自动替换。
4. 打开规则配置，选择保存的规则；检查本体当前工作内容，再进入校验与发布。

**结果**：工作内容保存 refs、固定版本引用及规则集合，可继续编辑；与已发布历史分开。

**失败处理**：版本冲突刷新本体和域；缺资源版本先补齐资产发布。删除被映射或 AI 建模历史引用的本体会被拒绝；没有引用的已发布本体删除也会清除历史，不能当作撤回按钮。

## ONT-002 设计器画布、检查器与布局保存

**问题**：如何整理复杂模型并检查某个员工类型或关系的配置？

**角色**：建模者、审阅者。

**前置**：登录后选择本体；查看无需编辑权限，保存需 EDITOR/ADMIN，且处在工作内容模式。

**操作**：

1. 从本体库进入设计器，或在设计器选择本体；使用资源池定位 Employee 或 BelongsTo（模拟）。
2. 点击节点/关系查看属性、端点、角色和版本；用图例核对未配置项。
3. 用画布工具移动/缩放和适配视图；需要整理时拖动节点，然后保存布局。
4. 不保留此次布局时取消；切换冻结版本可查看当时结构，返回“工作内容”后继续编辑。

**结果**：视图布局被单独保存，拖动节点不会生成语义版本；历史版本结构从冻结内容读取。

**失败处理**：加载错误先刷新，不把空画布当空本体。保存失败保留待保存布局后重试；多人同时存布局可能互相覆盖，需要约定单人整理。历史模式不能保存或改结构。

## ONT-003 本体发布、冻结依赖与版本演进

**问题**：如何保证组织模型发布后不会被上游类型修改悄悄改变？

**角色**：本体负责人、模型审阅者。

**前置**：EDITOR/ADMIN；所有本体成员已发布；规则保存版本与本体选择一致；必需检查可执行。

**操作**：

1. 在工作内容中检查模型和规则；必要时先运行资产层校验。
2. 点击发布，处理成员未发布、固定版本冲突及语义校验问题。
3. 发布成功后记录本体 ID 和修订，例如组织本体修订 1（模拟）；下游使用明确版本。
4. 升级上游类型后返回本体工作内容，显式调整引用和规则，再发布新版本；核对旧版保持原状。

**结果**：发布得到新修订和绑定本次冻结输入的报告；旧本体及下游已固定版本不会随新资源变化。

**失败处理**：旧报告不能授权改动后的模型；必需项 NOT_RUN 不可视为通过。规则更新后需要重新选择其版本。409 刷新工作内容再确认发布，不能省略令牌来绕过冲突。

[本功能台账、实现限制与源码测试](../product/features-modeling.md#ont-003)

## ONT-004 冻结版本历史与资源规则详情

**问题**：如何确认组织本体旧版本当时采用的员工属性和规则？

**角色**：模型审阅者、治理人员。

**前置**：登录；本体存在发布修订；访问的是已发布历史，而非当前资产详情。

**操作**：

1. 在设计器选择“冻结版本 1”，或在“本体交换”选择本体与修订 1（模拟）。
2. 打开 Employee 历史资源，检查 IRI、属性、默认值、基数、字典快照及校验和。
3. 沿冻结依赖打开关系或父类型；再打开规则查看当时的表达式和来源。

**结果**：看到特定发布版本的内容；当前类型和规则的后续修改不会替换历史显示。

**失败处理**：版本缺失或快照不完整时保留错误，联系维护者修复历史数据，不能拿当前资源补作历史证据。查看旧版不会回滚工作内容；需要复建时按交换恢复能力评估。

## ONT-005 AI 业务建模候选审阅与草稿应用

**问题**：如何把“员工属于部门、参与项目”描述转换为可审阅模型，而不自动发布？

**角色**：建模编辑者、领域专家。

**前置**：EDITOR/ADMIN；工作本体、默认 CHAT 模型、企业命名空间；拥有材料使用权限并明确同意发送给配置模型。

**操作**：

1. 进入设计器 AI 建模，选择企业命名空间，填写“员工属于一个部门，员工参与项目需记录开始日期”（模拟）。
2. 授权传输材料后生成；检查来源引用、复用资产、新增构造和阻塞问题。
3. 需要修正时编辑候选 JSON，填写修改说明并保存；再运行校验与计划预览。
4. 仅在必需检查 PASS/NA、无阻塞问题且内容未变时接受当前计划，应用到草稿；核对回执与资源映射。
5. 应用成功后返回设计器复核，再由本体负责人单独发布。

**结果**：获得带证据、修订和审计关联的候选及草稿变更；不会自动发布本体或修改已冻结资源。

**失败处理**：上下文/模型/候选变更使旧校验或确认失效，需重新生成/保存/校验。结果未知时先查回执，必要时用原 Idempotency-Key 重试；未查到回执也不等于回滚成功。不要更换 key 重复应用。

## ONT-006 AI 元数据补全与逐条确认

**问题**：如何补全草稿员工类型缺少的中文定义？

**角色**：语义资产维护者。

**前置**：EDITOR/ADMIN；配置默认 CHAT 模型；本体引用一个缺少中文标签或定义的草稿 ENTITY/ASSOC。

**操作**：

1. 在设计器打开 AI 补全并生成建议；例如为 Employee 补“组织中的在职人员”定义（模拟）。
2. 逐条阅读解释、资源 ID 和拟写内容；接受合适条目，忽略不合适条目。
3. 应用后刷新类型详情，确认只补缺失字段，再走正常资源/本体发布流程。

**结果**：缺失字段被填到草稿，建议状态改变并记录资产审计；已填写字段与冻结版本保持原内容。

**失败处理**：没有候选可能是无符合条件的草稿缺失项，不等于模型故障。上下文变化/旧建议缺基线时重新生成；结果不确定先查建议状态和资源详情，不以关闭面板认定服务器取消。

## GOV-002 规则库、来源及保存版本试跑

**问题**：如何把“员工必须有姓名”保存为可验证规则？

**角色**：规则维护者、模型审阅者。

**前置**：EDITOR/ADMIN 维护；VIEWER 可试跑保存版本。准备真实目标 IRI、规则来源、SHACL 表达式及正反例；例子见本节后方模拟数据。

**操作**：

1. 新建规则 `EmployeeNameRequired`，企业来源 `ENT-HR-001:3.2`，目标 Employee IRI，语言 SHACL，AUTO，严重性 VIOLATION（模拟）。
2. 录入属性必填形状、含姓名的正例和缺姓名的反例；保存后再试跑。
3. 确认总体 PASS 且正例符合/反例不符合；在本体设计器选择此保存版本。
4. 以后修改规则后重新保存/试跑，并在本体重新选择规则再发布。

**结果**：规则具有保存修订及来源；试跑结果只证明当前版本的这些正反例；本体发布可固定规则快照。

**失败处理**：NOT_RUN 表示未执行或上下文不足，不能当成通过。未保存修改先保存；版本冲突刷新。OWL 多个上下文或缺上下文时不能从试跑得出合格结论。删除被本体引用规则先解除工作引用并评估历史留存。

[本功能台账、实现限制与源码测试](../product/features-modeling.md#gov-002)

### 规则试跑示例（模拟）

下面是 GOV-002 的最小 SHACL 例子，规则目标为 `https://example.org/org/Employee`；实际系统应以已登记 IRI 和业务约束为准。

表达式：

```turtle
@prefix org: <https://example.org/org/> .
@prefix sh: <http://www.w3.org/ns/shacl#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .

org:EmployeeNameShape a sh:NodeShape ;
    sh:targetClass org:Employee ;
    sh:property [
        sh:path org:employeeName ;
        sh:datatype xsd:string ;
        sh:minCount 1
    ] .
```

正例（应符合）：

```turtle
@prefix org: <https://example.org/org/> .
org:employee001 a org:Employee ; org:employeeName "张三" .
```

反例（应不符合）：

```turtle
@prefix org: <https://example.org/org/> .
org:employee002 a org:Employee .
```

本轮未执行此例。规则库总体 PASS 要求正例符合、反例不符合；这只能验证所提供例子，不证明完整业务数据或标准合格。

## GOV-003 资产层四态校验与报告读取

**问题**：如何确认模型真的校验过，区分违反、未执行和不适用？

**角色**：建模审阅者、数据质量人员。

**前置**：运行需 EDITOR/ADMIN；查看已有报告可用 VIEWER；工作内容或发布版本已明确。

**操作**：

1. 在设计器运行校验，或在“校验报告”选择本体范围、目标本体及 WORKING/PUBLISHED。
2. 发布版选择明确修订；工作内容不选择历史 revision。
3. 查看逐项状态、定位资源与详细原因，同时记录报告 ID 和绑定的版本/digest。
4. 处理违反后重新执行；图谱实例范围需选图谱版本，不能用资产层报告替代实例校验。

**结果**：获得四态明细及汇总，能够辨别本次实际执行的范围和输入。

**失败处理**：NOT_RUN 先解决推理器/不支持构造/历史快照不足问题；NA 仅表示该项不适用。请求失败保留错误，不当作零违反。调整模型后旧报告不再证明新内容；导出报告由对应 API 提供 JSON/Turtle。

## GOV-005 完整 RDF 恢复预览与新本体建立

**问题**：如何在新环境建立一份导出的组织本体，同时避免覆盖已有模型？

**角色**：模型交付负责人、语义集成者。

**前置**：EDITOR/ADMIN；有权导入的 .ttl/.jsonld/.json；来源在支持子集内，建议先在隔离验收环境预览。

**操作**：

1. 在“本体交换→导入”上传文件或粘贴内容，确认格式；此过程不选择已有本体覆盖。
2. 先预览，核对本体名、来源版本、资源、枚举、依赖与未支持三元组。
3. 仅在无冲突且可应用时确认恢复；内容变动或预览过期后重新预览。
4. 成功后记录新本体 ID 与本地修订，打开冻结内容并重新导出比对支持语义。

**结果**：建立新本地资源和发布本体；原有资源不覆盖，源版本与本地版本分别显示。

**失败处理**：同名/同 IRI/命名空间不一致先解决冲突，不改 key 或删生产数据硬导入。未知/未支持三元组必须评估，不能静默丢弃。超限文件不可直接导入；409 或锁冲突重新预览。失败不宣称已恢复。

## GOV-006 按已有资源 IRI 导入草稿引用 API

**问题**：集成方如何把外部文件里已经存在的类型引用到一个草稿本体？

**角色**：接口集成者、建模者。

**前置**：EDITOR/ADMIN；目标本体仍为 DRAFT；拿到 current_revision 和 edit_revision；已有资源可按 IRI 匹配。没有页面向导。

**操作**：

1. 调用 import/preview，提交格式、内容与目标 ontology_id，逐项查看资源匹配和冲突。
2. 对未知资源用 SKIP；对可确认复用的资源显式 USE_EXISTING，不能用不同 resource_id 替换其身份。
3. 调用目标 import，带 If-Match 和最新 If-Edit-Match；核对返回的新增资源 ID 和跳过 IRI。

**结果**：只把已登记资源加入草稿引用；不会创建完整模型或改写本体历史。

**失败处理**：目标已发布、版本冲突或决策缺失时先刷新/修正。需要导入新资源或完整元数据时评估完整恢复能力；不要用 USE_EXISTING 假装按文件版本恢复。

## 通用失败处理

| 情况             | 处理                                                                        |
| ---------------- | --------------------------------------------------------------------------- |
| 登录失效 / 401   | 重新登录并读取最新目标；不要把身份失效当成空列表                            |
| 写入被拒 / 403   | 使用获准角色；VIEWER 可读不表示能运行持久校验或预览导入                     |
| 版本冲突 / 409   | 刷新对应资源、草稿与修订，人工合并后重新提交；保留编辑内容供比对            |
| 内容或语义不合法 | 按字段/原因修正；不绕过被拒绝的构造、默认值或版本冻结                       |
| 校验 NOT_RUN     | 保留未执行结论，解决依赖/支持范围/快照问题后定向重跑                        |
| AI 应用结果未知  | 查询回执与目标工作内容；仅使用原确认请求及原幂等 key 恢复，不新建第二次应用 |
| 导入/恢复冲突    | 重新预览、核对新建条件及支持语义；不能通过清理生产库来验证                  |

后续步骤见[数据到图谱](data-graph.md)、[知识库与系统](knowledge-system.md)及[快速入门](quickstart.md)。生产数据库本轮未操作。
